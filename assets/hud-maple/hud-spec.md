# 楓之谷風 HUD 改版規格

使用者已從六種風格中選定「1 楓之谷風」（對照 `/workspace/hud-research/v2/mockup-1-desktop.png`）。本規格供後續開單實作：探索 HUD、管理員「開發機狀態」頁（`/dev-status`）、島上「施工進度／路線圖」面板，三處共用同一套視窗鉻。設計稿見同目錄 mockup。本文件只規格，不施工。

視覺原則：粗海軍藍描邊、藍白視窗、淺天藍分頁、斜角＋內高光做出立體，不要糖果漸層、閃粉、毛玻璃。文字一律繁中。

## 2. 視窗鉻（Window chrome）

所有浮動面板與 `/dev-status` 卡片都用同一套：

- 圓角 `6px`（內框 `4px`）
- 外框 `3px solid #163A70`
- 內縮 1px `outline: 1px solid #A8D0F2`
- 硬陰影 `3px 4px 0 rgba(0,0,0,0.31)`（不要大面積柔化）
- 標題列高 32–40px（桌面 32–36，手機 36–48），底 `#3A7AC4`，底邊切平（不要半圓標題列）
- 標題列頂端再畫 1px `#78AADC` 實線當斜角高光
- 標題字：Noto Sans CJK TC Bold，白色，左邊 12–14px
- 關閉鈕（路線圖）：標題列右側金色方鈕 18–22px、2px 海軍藍邊、海軍藍 X
- 淺天藍分頁：未選 `#A8D0F2`＋海軍藍邊，選中白底並與本體相接；分頁高約 28px
- 頁面外框（僅 `/dev-status` 全頁）：最外 6px `navy`＋內 2px `blue-lt`，模仿遊戲客戶端外框

---

## 3. 字型

- 家族：`Noto Sans CJK TC` / `"Noto Sans TC"`，後備 `sans-serif`
- 粗體用於標題、按鈕、狀態、單號；內文 Regular
- 建議尺寸（桌面 1440 寬為基準；手機約 ×1.15–1.25）
  - 頁標題 26–30
  - 視窗標題 16–20
  - 區塊標題／工作列 14–16
  - 內文／子項 12–14
  - 標籤／Esc 晶片 9–11
- 數字與時間可用等寬，但不要換成英文像素字（那是風格 3，已落選）

## 4. 按鈕狀態

三種實心鈕，皆 3px 海軍藍邊、6px 圓角、內 1px `blue-lt`、頂端 1px 實心高光、硬陰影 `(2, 3)`：

| 種類 | 底 | 字 | 例子 |
|---|---|---|---|
| 主要（金） | `#ECC440` | `#163A70` | 退出探索（右上可疊 32×16 海軍藍 Esc 晶片、白字） |
| 次要（白） | `#F8FBFF` | `#163A70` | 自己開船、地圖、角色、開發機狀態、關閉 |
| 行動（藍） | `#3A7AC4` | `#FFFFFF` | 看施工進度、返回島嶼首頁 |

狀態：

- 預設：如上
- 懸停：底色加 8% 黑（或金改 `#E0B832`、藍改 `#326EB8`），不要加發光
- 按下：陰影改為 `(1, 1)`，整顆位移 +1px +1px
- 停用：底 `#D5DCE6`、字 `#8A96A8`、仍保留海軍藍邊
- 焦點：外加 2px `gold` 實線，不要 CSS outline glow

圓形圖示鈕（探索 HUD 右上 日夜／音樂／聊天／選單）：直徑約 44px（桌面），3px 海軍藍邊、白底（日夜為金底）、內 1px `blue-lt`；下方另附藍色小標籤板（2px 邊、3px 圓角、白字）。

---

## 5. 圖示風格

- 2–2.2px 海軍藍線稿＋簡單幾何，不要填滿漸層、不要拟物陰影
- 既有對照（與 mockup-1 相同）：太陽、喇叭、對話泡、漢堡、圖釘、人物
- 狀態點：10–12px 圓，2px 海軍藍邊；在線 `#2E9A4A`、離線 `#8A96A8`；左上可加 1px 白點當斜角，不要光暈
- 核取方塊：14px 方、3px 圓角、2px 海軍藍邊；勾選時海軍藍底＋白色折線勾

### 6.2 `/dev-status`（`dev-status.html` + `dev-machines.js` + `dev-machines-format.js`）

現況是米色頁＋白圓角卡。改為全頁楓之谷外框＋兩張機卡＋「最近合併」視窗。

| 現況欄位（`/api/dev-machines`） | 畫面上怎麼呈現 |
|---|---|
| `label`（猛虎／小貓） | 視窗標題 |
| （角色說明，前端寫死即可） | 標題下列「辦公室 Mac」／「家用 Mac」 |
| `online` | 標題列右側綠／灰徽章「在線」「離線」（3 分鐘內有心跳才算在線，既有 `ONLINE_WINDOW_MS`） |
| `issue` + `issueTitle` + 既有 `formatMachineWork` | 「工作」列：閒置／正在跑 #N 標題／等待 review・#N |
| `runStartedAt` + `formatRunDuration` | 「已跑時間」（閒置顯示 —） |
| `agentRunning` + `formatCursorLine` | 「Cursor」執行中（綠字）／未執行／狀態未知 |
| `battery` + `charging` + `formatBatteryLine` | 「電量」`81%　充電中` 或 `64%`（無資料則隱藏列） |
| `lastSeen` + `formatLastSeenAgo` | 「最後回報」剛剛／N 分鐘前／N 小時前／尚無回報 |
| `branch`、`commit` | 「分支」「提交」（離線或無資料則隱藏） |
| 頁首說明、30 秒輪詢 | 頂欄副標「每 30 秒更新 · 時間 台北」 |
| 頁尾「返回島嶼首頁」 | 藍色斜角鈕 |

**CPU／記憶體：現有 API 與心跳 payload 沒有這兩個欄位**（`DevMachineStore.Snapshot` 只有 issue／branch／runStartedAt／agentRunning／commit／battery／charging）。本 mockup 因此不畫假的 CPU 條。若產品之後要顯示，再擴充心跳與 `listForApi`，不要在前端捏造。

**最近合併：現況 `/dev-status` 頁沒有此區塊。** 建議加在兩張機卡下方，資料可重用既有 `/api/dev-status` 的 `timeline`（action＝已合併，且 `at` 落在當日 00:00 台北之後），或另查 GitHub 已合併 PR。標題「最近合併」，註記「今日（台北）已合併 N 項」。這不是假資料，是把既有開發進度資料搬到管理員頁。

機卡資料在 mockup 裡是 11/19 15:31 台北的示意快照（猛虎閒置、小貓示意正在跑 #205），實作時一律吃即時心跳，不要寫死。

### 6.3 路線圖面板（`island-roadmap.js`，讀 GitHub #36）

現況：告示牌打開後，只畫各期標題＋`phase.done` 對應的已完成／施工中／未開工，子項是把標題冒號後的文字用「、」切开，沒有勾選、沒有比例、沒有「今日完成」。

改為島上置中的楓之谷視窗（背景島嶼畫面不變，只蓋一層實色遮罩 `rgba(20,36,64,0.47)`，不要背景模糊）：

| 現況 | 改成 |
|---|---|
| 標題「第 N 期施工中」 | 視窗標題「施工進度」，黃條頭條寫「第 5 期施工中　博弈島室內」（`signCopy` 邏輯可沿用） |
| `<details>` 期別列 | 海軍藍邊列：勾／●／▸、期名、扁平進度條、`done/total`、狀態標籤（綠已完成／金施工中／灰未完工） |
| 展開後的純文字清單 | 可勾的子項（☑／☐）＋單號 |
| 無總進度 | 頭條右側「子項合計 done/total」＋金進度條 |
| 無「今日完成」 | 桌面右側獨立視窗；手機放在期別清單上方。列出當日台北已合併的 PR（時間、#issue / PR #n、標題）與「今日已合併 N 項」 |
| 「資料來源：GitHub #36」 | 視窗底列保留連結 |
| 管理員才看得到的「開發機狀態」連結（`mergeRoadmapDevStatusLink`） | 底列白色斜角鈕，權限邏輯不變 |
| 開發進度表、篩選、時間軸（`/api/dev-status` 那一段） | 本 mockup 先把焦點放在路線圖本身＋今日完成；表格式開發進度若要保留，可再加一個淺天藍分頁，鉻不變 |

**Parser 要擴充**（`RoadmapParser.java` 目前只讀上級 `- [x] **Phase N**`，子項只用「、」切开、沒有個別勾選）：

1. 解析上級清單下縮排的 `- [x]` / `- [ ]`，保留 `done` 與原文。
2. 完成比例 = 已勾子項 / 子項總數。沒有子項時：上級已勾＝1/1，未勾＝0/1（若上級冒號後有「、」分隔且無子項勾選，可把那些詞條當成未勾子項，例如「穿插」0/3）。
3. 上級未勾、但子項尚未涵蓋分期說明裡的剩餘工作時：不要把 1/1 畫成金條滿格又標「施工中」。處理方式與 mockup 第 5 期相同——把分期說明中尚未獨立開勾的目標（拉霸機、輪盤、幸運轉盤）一併列入分母，並加一行短註「21 點已在大廳可玩。」第 5 期因此為 1/4、施工中。
4. 無編號的分組（建築 GLB 重做、穿插、介面與氛圍…）同樣列在清單裡；子項全勾則標已完成，即使上級 checkbox 還沒勾。
5. `current` 仍是第一個未勾的有編號 Phase（現在是 Phase 5 博弈島室內）；該列預設展開。
6. 「今日完成」不要寫進 #36 本文；用已合併 PR（或 `/api/dev-status` timeline）篩 `Asia/Taipei` 當日 00:00 起。Mockup 用的是 2026-11-19 實查結果：當日已合併 31 項，列出最近 8 筆（#209/#210 傳檔 400 MB、#193/#195 賭場 v3、#204/#208 小綿羊、#202/#206 下車、#188/#198 行人看板、#191/#192 退出探索、#196/#197 各島音樂、#190/#194 抬頭鏡頭）。

施工中定義維持現況：`phaseStatus()`——已勾＝已完成；有編號且等於 `current`＝施工中；其餘未勾＝未完工。

## 7. 手機版面

斷點建議：`< 720px` 改單欄（與現況 dev-machines 網格一致）。觸控點至少 44px 高。

**開發機狀態**

- 頂欄全寬藍底：標題＋「每 30 秒更新 · 時間 台北」
- 猛虎、小貓、最近合併三個視窗直向排列
- 最近合併改兩行（時間＋單號／標題），不必硬套三欄桌面表
- 底固定「返回島嶼首頁」藍鈕

**路線圖**

- 視窗幾乎全螢幕，保留關閉 X
- 先放頭條「第 N 期施工中」，再放「今日完成」（先列 6–8 筆＋當日總數），再放可捲動的各期清單
- 施工中與尚未做完、且有子項的期別（mockup 展開第 5、6、8 期）預設打開；已完成列收合
- 底列保留 GitHub #36 與「開發機狀態」鈕
- 不要在手機上並排左右欄

探索 HUD 手機配置已有 mockup-1-phone：玩家卡在上、圓鈕在右上、搖桿在左下、退出／開船／地圖／角色／施工進度在右下。
